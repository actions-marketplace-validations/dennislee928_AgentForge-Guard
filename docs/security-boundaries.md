# Security Boundaries

**Prompt instructions are not a security boundary.** Real boundaries are OS sandboxes, filesystem permissions, cloud IAM, Kubernetes RBAC, database roles, scoped tokens, network policy and human approval. `afg` adds a policy layer and execution backends on top of these; it does not replace them.

## Two modes, two levels of assurance

### Managed mode: `afg run -- <argv>`

`afg` itself evaluates the policy and spawns the process:

- argv is structured; there is never an implicit shell.
- The executable is resolved to a canonical absolute path.
- The environment is cleared to an allowlist.
- Approval is read only from the controlling TTY.
- Container runs use a filtered snapshot with no network.
- Every decision is written to the audit log.

This is the only mode in which `afg` **enforces** policy.

### Integration mode: agent hooks and settings

Claude Code hooks and permission rules, and Codex sandbox and approval settings, call the same policy engine. Their strength is bounded by:

- whether the agent routes every action through the hook (some tools, such as file reads and network access, may not go through `Bash`);
- how the agent tokenizes shell strings, since `afg` can only classify what it is shown;
- the agent's own sandbox.

Integration mode is **defense in depth, not enforcement**. It must never be advertised as equivalent to managed mode.

## Remote sandboxes do not protect local secrets automatically

A remote or container sandbox cannot read host secrets **unless they are sent in**. However, an agent running on the host with filesystem access can still read `~/.ssh` and send it elsewhere. You also need:

- Agent-level read deny rules for protected paths (generated by `afg agents sync`, v0.2).
- Manifest-filtered uploads that exclude `.env*`, keys, certificates and git-ignored files.
- Least-privilege credentials and no production credentials on development machines.

## Non-claims

- Allowing `go test` or `cargo test` does not make the tests safe. Test binaries can do anything.
- Matching argv does not prove a command is harmless.
- Docker isolation is only as strong as the Docker runtime and kernel.
